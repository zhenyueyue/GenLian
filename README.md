# 跟练 GenLian

原生工程位于 `ios/`。`prototype/docs/` 的六份交接文档与 `prototype/src/components/warm-performance/` 是页面和素材的设计基准。

## 阶段 1A

| 位置 | 内容 |
| --- | --- |
| `ios/GenLian.xcodeproj` | iPhone 应用 Target 和共享 GenLian Scheme，最低 iOS 26 |
| `ios/GenLian` | SwiftUI 启动入口与 Warm Performance 基础颜色 |
| `ios/Sources/TrainingCore` | 四套内置课程、动作与负重模型、训练状态机、计时协调器、本地存储 |
| `ios/Tests/TrainingCoreTests` | Swift Testing 用例，覆盖四套课程、训练中断、时钟变化、恢复和归档 |

应用 Target 已引用本地 Swift Package。

### 训练与存档

- 每条组实录以轮次、动作位置、组号和侧别识别。双侧动作记一条，单侧动作可先练任一侧，两侧各有独立实录。回看上一动作保留当前训练位置。
- 休息由最后一个完成侧触发。跳过会记下相关未完成项。正式结束会保留 0 组或部分实录，主动暂存则冻结当前阶段并保留同一会话供恢复。
- 前台使用单调时钟。系统切到后台时，准备、确认、动作与过渡冻结，已开始的休息照常计时。自动休息到期后，返回前台进入下一动作的完整过渡。主动暂停冻结休息。进程重启后按最后一次写盘时间恢复休息，时钟被调早时将时间差限制在零。
- 会话计时包括第一组开始后的训练、休息与阶段过渡。动作耗时、实休时间和主动暂停单独保留，次数与秒数独立统计。
- 阶段 1A 的存储采用带版本号的本地 JSON。每次关键操作、阶段变化和进入后台写盘，计时中每 15 秒检查一次是否需要存盘。结束时先保存可恢复的总结，点击「收入个人训练档案」时将当前会话与历史在同一次原子替换中提交。强制终止可能丢失最后一次存盘后的计时增量。
- 档案从空数据开始。配重默认未设置，徒手动作按徒手记录。库存计算只检查两只、四侧对称的装片是否超出已知库存。

### 构建与验收

有 Swift 6 工具链的主机可运行领域测试。测试使用注入时钟和临时存储。

```sh
swift test --package-path ios
```

Mac 上用包含 iOS 26 或更新 SDK 的 Xcode 打开 `ios/GenLian.xcodeproj`。可先用共享 Scheme 验证模拟器目标构建。

```sh
xcodebuild -project ios/GenLian.xcodeproj -scheme GenLian \
  -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
```

连接 iOS 27 的 iPhone 15 Pro Max 做真机验收时，使用支持该系统的 Xcode 并配置开发团队和 Bundle ID。当前 `com.genlian.app` 是工程预留标识。阶段 1A 的 Windows 环境中，Swift 测试执行、Xcode 构建、模拟器和真机仍待验证。

## 阶段 1B

原生页面覆盖今日、动作详情、全屏跟练、组间休息及配重与休息抽屉。训练视图把操作发送给同一个 TrainingCore 会话，由应用入口处理前后台切换。次数或秒数、单组实际负重和未完成侧的草稿与会话一同保存。定时动作默认记录实际动作秒数，也可手动修正。

素材采用冻结原型的 13 张晨光照片。罗马尼亚硬拉、侧平举使用明确的缺素材状态。全屏舞台在目前可用资产下以静态姿态参考呈现。

Mac 和真机验收优先复现以下流程。

1. 力量 A 开练，调整第一组次数和实测负重，完成后微调实录。自动进入休息前的倒数应在实录编辑时停住。
2. 休息时暂停与继续，调整或提前结束休息，检查实休时间与下一动作。单臂动作分别确认为左侧、右侧，检查重复触碰的结果。
3. 恢复日设为手动推进，观察实际秒数、组间休息到期后的「就绪」。锁屏或终止应用后恢复，核对组实录、待完成侧、负重草稿和休息。
4. 提前结束或完成四课任一课程，通过训练总结入口归档一次。检查数据写入失败时界面显示错误，且保留可重试的会话。
5. 在 iOS 26 和 iOS 27 检查 Liquid Glass 的系统渲染、暂停与休息舞台、状态栏、44 pt 控件、动态字体、VoiceOver、减少动态效果和降低透明度。

## 阶段 1C

总结、档案列表、月历和历史详情读取 TrainingCore 的会话及归档快照。四个页面共用领域层的统计口径。每侧独立记一组，每轮中的同一动作只有在计划组和侧别均完成时才计为完成动作。次数、秒数和重量按各自单位显示。有效时长取已有的会话计时，包括已计入的动作、实休和阶段过渡。档案累计统计按课程分类汇总，零组记录仍可查看。

月历按训练**开始时的本地日期**归档，同一会话跨日或跨月只显示在起始日。同日多次训练保留各自的详情。新会话保存可选的 `timeZoneIdentifier`，旧的 v1 存档没有该字段时使用查看设备的本地时区。存储文件仍为版本 1，首次读取无需重写旧数据。已有课程、动作顺序、目标、实录和归档 ID 都继续使用原快照。

原生验收时运行 `swift test --package-path ios`，再执行前文的 Xcode 构建。真机核对归档后重启、同日多条记录、不同月份、跨日日期显示、存储失败重试、详细页返回和 Dock 导航，同时检查 iOS 26/27 玻璃材质、动态字体、减少动态效果和降低透明度。

## 阶段 2A · GitHub Actions 原生验证

`.github/workflows/ios-ci.yml` 使用 `xcode-27` Apple Silicon Runner，记录实际工具链版本，运行 TrainingCore 测试并对 GenLian Scheme 执行免签名的 iOS Simulator 构建。工作流查询可用的 iPhone 模拟器，再尝试安装、启动和截图。有可用模拟器且 Scheme 配置了测试目标或测试计划时，也执行 `xcodebuild test`。

首次运行需要将工作流同步到 GitHub 私有仓库的默认分支，开启 Actions 并由具备写权限的身份手动触发。运行耗用仓库所有者的 Actions 计算用量，上传的诊断包占用存储，超出账户额度可能收费。

在 Actions 运行页面下载 `genlian-ios-ci-<运行尝试次数>`。诊断包包括工具链和目标清单、Swift 测试日志与可用的 xUnit 报告、iOS 构建日志和生成的 `.xcresult`、资源检查及可用的模拟器启动证据。没有兼容模拟器或 Scheme 未配置测试时，选择日志会注明跳过的验证。
